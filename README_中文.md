# 原琴 MIDI 双路桥 · 0.18

适用于鸿蒙 4.x 的安卓 APK 兼容环境。实体 USB MIDI 键盘或导入的 MIDI 文件同时驱动本地采样音源和原神21键触控。实际 Android API 至少26；USB输入需要系统 MIDI 服务，游戏触控需要用户开启无障碍。

## 更新安装和无障碍

0.18与0.2–0.17的包名、无障碍服务组件、签名证书保持一致，已核对证书摘要。**先停止旧版音源，再直接覆盖安装，不要先卸载旧版**。通常保留无障碍开关、绑定包名、校准、自定义采样及已录静音/开声步骤；鸿蒙若重置无障碍状态仍需手动开启。普通应用不能自动替用户授予无障碍权限。

## 0.18：长按触点复用与平板兼容检测

0.17为避开系统触点编号累积，在兼容重接时会松开并重新按下仍保持的音，所以低音和弦可能重新响一次。0.18新增固定10个触点槽的实验方案：保持中的音沿用原槽，已松开的槽可供新音使用。新路径不再因累计起音次数而整组松开重接；同时超过10个映射键仍按既有上限处理。

### 安装后的操作

1. 停止旧版音源，覆盖安装0.18；在“04 · 设置”确认无障碍已开启。
2. 打开“03 · 调音与声音”，点击 **“检测并启用触点复用（约3秒）”**。检测时暂时不要碰屏幕，不需要连接MIDI键盘或校准琴键。
3. 检测通过会自动开启“实时键盘：按下保持触控，松开释放”和“长按时复用触点（避免保持音重新起音）”。回到原神，再从悬浮球开启映射，测试保持低音并连续弹上方旋律。

检测在应用自己的全屏触控面板运行。它使用与实时映射相同的手势构建路径，实际收集收到的触控事件，检查保持音有没有再次按下、触点有没有取消或串键、21键轮换及10键换组是否完整释放。测试会先暂停游戏触控和文件演奏；结束或取消后不会自动恢复游戏映射。离开应用、屏幕尺寸变化或超时会终止检测，清理触点。检测未通过会显示原因并关闭触点复用，保留原有实时长按选择；可重新检测，或取消复用使用旧兼容模式，或取消实时长按使用完整松键的短点按。

检测通过记录与当前系统版本绑定。系统更新后应重新检测。新路径每次提交也检查系统是否读取了复用标识；异常时关闭映射并请求释放，不在持有和弦时悄悄切换回旧路径。旧回调、重复回调、取消后回调不能提交新的触点槽或恢复已经松开的键。

这一方案使用公开的StrokeDescription构造器与continueStroke，扩展类的getId/getContinuedStrokeId依赖系统内部对同名虚方法的调用，没有反射或额外权限。此内部行为并非Android公开兼容承诺；因此先做平板检测，再启用游戏映射。**今后若启用混淆，不得重命名ReusableStroke的这两个方法。** APK没有新增第三方运行库、图片或音频。

实际运行全部纯Java回归，新增401799项槽位归属、用户音程序列、长时间保持/换音、同键再按、超限及检测轨迹断言。另将生产手势类先按真实公开API35编译，再接入未修改的AOSP Android12手势与注入器源码执行，102544项断言通过；包括72包应用检测序列、保持低音的2000次琶音/全音域换音及1000次用户音程序列。后者运行在JVM平台替身上，不能替代鸿蒙ART、系统实际注入或原神琴声实测。

APK编译、v2/v3签名、对齐和完整性检查通过，沿用旧版签名。21个WAV、图标、背景及装饰素材字节保持；本地试听自动开声、音频缓冲、MIDI文件速度/转调、文件短点按及其他功能沿用0.17。**平板检测通过也不能保证原神所有卡顿、漏音或崩溃都已解决，实际听感仍需在用户设备验证。** 以下保留历史版本更新。

## 0.17：试听自动开声与实时多键续接

**本地MIDI试听开始/继续时自动取消本地静音**，已经有声时保持有声，不会反向切成静音。保留用户设定的音量，并将本地静音偏好更新为关闭；悬浮菜单若已打开，按钮文字同步为“本地音源静音”。仅在本地试听成功准备起播时处理；无文件、解析失败、音源未运行时不改静音。原神文件演奏不自动开本地声音，试听过程中仍可手动静音，不会被进度刷新重新取消。此操作不调整系统媒体音量，本地音量滑块为0时也不自动调高。

用户反馈手动弹奏低/高音程连续变化时卡住，及保持“−1、−5、1”后琶音“+3、+7”会漏高音。核对0.14、0.15源码：实时触控模块逐字节相同，所以不能仅凭版本名称确定根因；0.16也继续使用同一LiveTouchState/LiveTouchPlan/HoldMotion。这次找到之前离线检查未覆盖的系统指针编号约束。

AOSP MotionEventInjector会保留已释放指针的编号映射，直到整个持续手势的最后一个手指松开才清空。只看同时保持几键不足以判断兼容性：保持低音并反复加入旋律音时，累计新起音可耗尽可用编号，导致重复指针ID。已核对公开Android12和当前主分支的编号分配/清空逻辑；鸿蒙上的实际实现及用户卡住的全部原因尚未取得日志确认。

新增LivePointerBudget，统计同一持续触控链累计分配的新指针，而非仅统计同时键数。在下一次新起音将超出10个编号前，先用所有旧手指的闭合续接请求完整松键；确认系统完成后，再根据当前物理MIDI按键重建。物理按键引用计数和待播放短音不清空，旧来源已松开的键不重新保持；新的MIDI输入在等待完成期间仍正常入队。自然全部松键本来就能清空编号，不额外插入重接；仅静态保持和弦也不会因时间经过而重接。过期/取消回调沿用代次保护，失败仍关闭触控并请求释放。

**兼容重接有取舍**：仍按住的键会短暂松开再按下，原神可能重新响一次低音和弦；这是重新建立系统多指序列的结果，不保证持续触控无缝。1ms是计划中的松键段时长，真实间隔还包括系统回调。若更重视原神琴声起音稳定，可在“调音与声音”取消“实时键盘：按下保持触控，松开释放”，保存后重新开启映射，用已有24ms完整松键短点按。该设置不改变本地采样时值或文件演奏设置。状态会短暂显示“多指兼容重接”及累计次数。

新增90118项回归断言，使用实际LiveTouchState/LiveTouchPlan/LivePointerBudget，加上按公开系统规则建立的独立编号模型：复现旧连续音程序列在同时最多4键时仍产生重复编号，保持三个低音的高音琶音在同时最多5键时也能复现；新版模型覆盖连续100轮音程、150轮高音琶音、+2配合其余20键、长期静态和弦、完整10键换组、折回来源共享、重接中到达的松键/短音及过期回调。新物理起音仅发送一次；兼容恢复会额外重触发仍保持的键，检查中分别计数。

全部既有纯Java回归和Android编译、最终APK签名校验通过，音色/背景/图标字节保持。音频混音、缓冲自适应、0.16文件调度、BPM覆盖/转C、文件长按停用策略沿用。**编号模型不是鸿蒙或原神实测**，不能保证已解决设备上的全部卡顿、漏音或崩溃。以下为历史版本更新。

## 0.16：文件漏音、节奏调度与长按兼容处理

用户反馈MIDI偶发漏音、间隔卡顿，以及选择文件“按音符时值按住”后原神崩溃。代码检查并复现了两个漏音机制；没有鸿蒙真机日志，不能确定游戏崩溃的唯一原因，也不能保证这两个机制解释了设备上的全部现象。

- **本地文件音源**：旧主线程一旦晚处理，可能把一个短音的按下与松开一起送入音频队列；混音先处理全部消息，音量包络还没起音就被松开，输出可以完全为零。新增FileAudioSequence，由音频线程在生成PCM时按音符边界分段混音，不再用界面定时器逐个发音符。已有毫秒时间线转换为采样帧位置，保留空拍、同时起音、时值和释音。界面每100ms读取进度，不负责奏音。
- **起播准备**：等待内置/自定义WAV加载完成后才开始倒计时；暂停会取消当前音频序列并保存它的渲染位置，继续时只恢复跨过暂停点的长音，按剩余时值释放。停止和过期回调不能重新起奏。倒计时只使用固定起播时间，避免渲染进度提前时界面误回到倒计时。
- **游戏短点按**：旧逻辑按当前时钟重新找音，回调晚到时会跳过整个24ms窗口都已过期的未发送短音。改为按已经完成的音符序号推进，预先计划最多800ms范围内的完整闭合点按，仍遵守系统手势条数上限，且不拆开同一时刻的和弦。迟到不超过120ms时保留下一音的完整点按和本批相对间隔；超过120ms会暂停并提示降低文件速度或减少音轨，避免持续积压。
- **文件长按暂时停用**：移除文件续接长按执行路径，文件触控只提供“琴类短点按”。升级时一次性将旧midi_hold设置关闭，不改速度、原调、音轨、采样、校准或声音操作记录。本地文件仍可按MIDI时值收音；实时USB键盘按住/松开映射继续保留。游戏琴声时值仍取决于游戏乐器。

游戏点按最多24ms，极密集的同键重触发会缩短，以保留松键间隔。Android/游戏帧处理仍可能无法识别非常短或非常密集的触控；这次不把每个已完成系统手势等同于游戏一定发声。程序配置为忽略调外音、过滤鼓轨、排除音轨或合并同键时，也会主动减少音符，播放状态显示映射与跳过计数。

输出缓冲仍使用既有低延迟/平衡/稳健档及欠载后自动增大机制。如果“缓冲不足次数”持续增加，可选择平衡或稳健后保存；“过一会好些”可能与缓冲适应或加载结束有关，但尚未在用户设备证实。新的音频序列保留各音在实际生成PCM中的间隔，不跳过逾期短音；真实AudioTrack断流、系统调度或游戏负载仍可造成卡顿，双路声音的实际同步也未实测。

状态中的“音源起播迟到”是音频线程开始渲染相对软件起播时间的迟到量；“触控最大迟到”是各批提交时相对该批首个未发送音的迟到量。二者均不包含输出缓冲、硬件声学延迟或游戏实际发声时间；进度取音频渲染位置，也不等于扬声器当下听到的位置。

新增1764项文件音频/触控时序断言，包括旧漏音复现、1ms短音可发声、44.1/48/96kHz与多种块大小、主线程模拟不规则更新、和弦、休止、暂停点恢复、停止、静音连续性、迟到短点按保留、超时暂停、重复回调和不拆和弦。全部现有核心检查、Android编译和APK签名校验通过；仍未在鸿蒙/原神真机验证。0.15的目标BPM覆盖和原调转C调继续保留。以下为历史版本更新。

## 0.15：固定目标BPM与按原调转C调

MIDI文件页新增两个默认关闭的开关。升级后仍保留原速度百分比，并默认按已转为C调的文件处理。

- **覆盖原始速度（Override）**：开启后输入20–400 BPM，支持小数，默认120。用目标BPM贯穿全曲，忽略文件内所有速度变化，旧速度百分比暂不生效；关闭后恢复原速度地图和已有百分比。音符起音、时值、空拍、曲尾休止和延音踏板都按原始PPQ刻度重新计算，不量化到格子。短点按模式仍保留完整24ms游戏按键；本地采样和实验长按按新的文件时值处理。
- **按MIDI原调自动转为C调**：开启后从12个“大调 / 关系小调”选项选择原调，默认C大调 / A小调；A小调按C大调处理，B小调按D大调处理。按整首单一调性转调，不跟随文件中的调号变化。使用就近的移调区间−6至+5半音，之后执行原有调外音修正和八度折回；关闭时不执行文件原调转换。“调音与声音”页的共同移调继续额外生效，通常应保持0，避免重复转调。

例如原文件为D大调、带120→60 BPM变速：开启转C调并选“D大调 / B小调”，再开启覆盖并填90，全曲会先整体降低2半音，起音和松键统一按90 BPM重新安排。A小调选“C大调 / A小调”不会把主音A误移到C；它保留A小调关系调中的音级，仅使用C调的自然音键位。

设置好后点**保存文件演奏设置**，再从头试听或回到原神用悬浮球开始演奏。保存会停止当前文件并释放按键，避免暂停后继续使用旧时间线。四个新增字段有固定View ID，偏好持久保存，页面切换和Activity状态恢复沿用原机制。播放状态会显示固定BPM/原速度百分比及所选原调。

固定BPM仅支持使用每拍刻度的PPQ MIDI。SMPTE按绝对时间编码的文件仍可按原时序/百分比播放和转调；尝试覆盖时明确提示关闭覆盖或导出为PPQ MIDI。覆盖后目标时长超过6小时也会提示提高BPM。原始选中MIDI文件不被改写，关闭覆盖可恢复完整原速度变化。

新增390项纯Java检查，覆盖变速曲重计时、非整拍起音、小数BPM、关闭开关恢复旧行为、不叠加百分比、休止/踏板/控制器释放、缺失Note Off、多轨、零刻度音、12个大调/关系小调、调外音处理顺序、八度折回、鼓通道过滤和限制提示。Android编译、全部现有回归及APK签名验证通过；没有本次鸿蒙真机或原神运行实测。音频缓冲、实时键盘映射、悬浮菜单和动态背景沿用0.14。

## 0.13：参考四叶草与交替十字辉光

根据本次两张参考图，四叶草继续使用代码绘制，随机采用绿叶配白边的尖叶款，或白叶配浅绿描边的圆叶款。缩放半径仍为5–9dp，和0.12相同，保留随机大小、初始旋转及缓慢摇摆/飘落。花瓣沿用原来的绘制路径。

原来的淡黄色星形改为两条短线组成的小十字。每个粒子使用8秒循环：0–2.4秒翠绿色辉光渐亮再渐暗，2.4–4秒完全熄灭，4–6.4秒浅黄色辉光渐亮再渐暗，6.4–8秒完全熄灭，然后重复。不同粒子的周期起点随机错开；熄灭时十字和辉光都不绘制，背景的原图仍保留自己的装饰。

十字尺寸稍增至半径3.5–5.5dp，主线提高不透明度，并用预先创建的径向渐变绘制柔和辉光。翠绿比浅色背景深，浅黄保持柔和。粒子仍缓慢下落，数量12个，位于背景层两侧；中央白色页面继续遮挡背景。动画只在应用前台可见时运行，切回游戏或关闭动态背景时停止。

## 0.8：悬浮球、双键续接与静音首步

左上角横条改为36dp小悬浮球，默认靠右。可拖动并记住位置，横竖屏改变时会回到屏幕范围内；点一下展开菜单，再点球或点“收起”可收起。开启实时映射或文件演奏后菜单自动收起。长按球约0.5秒紧急停奏。

打开菜单或拖动球时先暂停游戏触控、松开旧手指；实时键盘本地采样继续，游戏文件播放会暂停。操作菜单时USB键盘不会点击菜单按钮。点“开启映射”恢复实时键盘，或在“MIDI文件”里继续演奏。开启实时映射会停止文件模式，恢复USB输入。校准位置与球重叠时尝试将球移开；运行中若仍遮住琴键则停止触控并提示移动。

0.7在已有手指保持时，把新琴键也放在续接手势的第0毫秒。AOSP会校验首个步骤只包含旧的保持手指，额外的新手指使校验失败。0.8让旧手指从0毫秒续接，新键在2毫秒加入，其他键继续保持。文件实验长按模式同样错开边界上的新手指。2毫秒是手势计划中的偏移，不是实测触控延迟。

旧恢复点位于左上角“MIDI文件”按钮区域。0.8恢复时关闭操作菜单，用完整屏幕的消费触控层承接新的闭合手势，恢复点移到拦截层中间；既要收到系统完成回报，也要确认拦截层实际收到松开，再延迟撤掉。等待或失败时不会展开操作菜单（这一失败后门禁已在0.9改为只阻止游戏触控，菜单可用）。触控取消回报可能早于真实手指到达悬浮球，恢复会短暂等待，拖动期间延后到松手后执行，避免恢复手势打断拖动。

游戏静音保存与回放继续使用屏幕绝对坐标归一化。录制层启动后短暂等待，只接受同一手指完整按下、松开的操作；启动对话框遗留的松开、取消、换指或多指不会写成第1步。录制坐标由视图位置与触点相加得到屏幕位置。回放每一步之前撤掉控制层，等它退出后再注入，完成后恢复取消按钮，避免首步或其他步骤点到本应用控件。

**旧静音步骤保留。若只有第一步错误：回到原神琴界面 → 点悬浮球 → 声音设置 → 游戏静音 → 仅校正第一步 → 点左上角本来要点的位置。** 这个操作只保存坐标，不会立即点击游戏；后续步骤及原第1步的时长、等待保留。设置会显示第1步在左上/右上等位置和相对屏幕的百分比。全套重录仍可用，屏幕尺寸改变则需重录。（路径按0.11菜单更新。）

离线检查已覆盖多键加入时首步的旧手指集合、球与菜单的边界/记忆位置/避键、左上坐标保持、丢弃孤立松开以及只校正首步时保留其他步骤。实际鸿蒙输入窗口注册、事件交付、拖动、长按、静音回放和持续多指仍需装机验证。

## 0.7：实时键盘跟随按下和松开

实时USB映射默认改为“按下保持触控，松开释放”。应用的音高设置里可关闭此选项，恢复原来的24ms短点按；修改后点保存设置。MIDI文件触控仍有独立设置，默认琴类短点按。

- 每个MIDI通道和原始音高分别记录按键。按住C再按E，两键同时保持；只松开C时，E仍保持。Note Off及力度0的Note On均释放；重复发送同一Note On不会重复增加持有次数。
- 八度折回或不同通道映射到同一琴键时共享一个屏幕手指，所有来源都松开后才释放。实时延音踏板仅控制本地采样，游戏触控跟随实际松键。
- 最多同时保持10个不同琴键。多指切换先释放旧键再按新键；系统手势条数较少时分批处理。0.7–0.8超过保持上限或积压64次起音时停止映射并请求松键；0.9改为只忽略超出的输入，继续映射，状态栏显示原因。
- 快速同键重按会先松再按，其他仍按住的键继续保持。短促按下/松开在当前手势尚未完成时会排队保留起音；这种极短音至少点按24ms，密集连奏可能迟到。正在保持的键不会每段重复起音。
- 长按用24ms短段连续续接，在键中心附近交替移动1像素，避免静止续接没有事件。新的起点与上段终点相同；松键沿用当前终点。触控回调晚到会增加跟随延迟，24ms不是端到端实测延迟。
- 关闭映射、紧急停奏、拔出键盘、切离原神、屏幕变化或无障碍中断时清空按键并请求取消旧触控。系统取消、拒绝或超过回调期限时关闭实时映射并恢复松键，过期回调不能重新挂住旧手指。游戏静音先等待触控释放，再显示录制层或重放步骤，避免把恢复手势录进去。
- 本地文件试听开始时也关闭实时触控，避免文件播放屏蔽USB松键消息后遗留按住状态。游戏文件演奏需先松开键盘或关闭映射，两种触控模式不会同时提交。

长按能否持续发声由游戏乐器决定；本地WAV仍按采样长度和自然衰减设置播放，不会自动循环拉长。此版已编译并通过离线回归，鸿蒙4.x的持续触控、松键和多指兼容性仍需实际安装验证。

建议装机检查：按住C约2秒→保持C再按E→松开C、确认E仍保持→松开E；接着试三键和弦、快速同键重按、保持时紧急停奏和拔线。若系统拒绝续接，可取消实时长按选项后保存设置。

## 0.6：首音按住、后续停奏修复

0.5的长按续接使用静止路径。AOSP注入器只有坐标变化、按下或松开时才生成触摸事件；中间一段静止续接可能没有任何事件并返回失败。旧取消分支随后清掉了仍按住的手指记录，无法再松键。这与用户反馈的“采样正常，游戏在首音停住且一直按住”相符，具体鸿蒙行为仍需真机验证。

- 长按续接在琴键中心附近交替移动1个像素，使续接始终产生移动事件；下一段起点与上一段终点一致。最终释放沿用当前终点，避免触控坐标不匹配。仅改变触控路径，不改MIDI音高和本地音源。
- 琴类短点按每一批都包含完整松键，即使24ms点按跨过100ms计划边界，也不会变成保留手指的续接。短点按默认开启；首次升级会把旧文件长按设置切为短点按，其余MIDI/采样/校准数据保留，可自行重新选择实验长按。
- 每个文件手势有“预计时长+600ms”的回调超时。超时会暂停并请求取消旧手指，延迟到达的旧回调不会覆盖新的播放或恢复状态。
- 停止、取消和超时使用一个新的闭合手势取消旧触控；这次手势落在本应用临时的触控拦截层内，避免在游戏里额外弹音或误触其他应用。恢复层布局就绪后才提交。正常释放/取消/恢复回调有代次校验，恢复本身也不会无限等待回调。系统拒绝恢复时显示重新开启无障碍服务的提示。
- 文件播放采用最多10个同时触控作为兼容上限；单个批次的手势条数仍由系统API决定。超过同时触控上限提示减少音轨或改短点按，不默默漏音。

先停止旧版音源并覆盖安装，打开应用确认当前版本。保留默认“琴类短点按”，保存文件设置，回到琴界面从头演奏。本地采样仍根据MIDI时值进入释音；游戏琴声的长短由游戏乐器决定。

故障机制参考：[Android AOSP MotionEventInjector](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/accessibility/java/com/android/server/accessibility/MotionEventInjector.java)。离线验证能检查该机制、手势计划和回调状态机，不能代替鸿蒙及原神内的实际运行测试。

## MIDI文件自动演奏（当前版本）

1. 点“导入 MIDI 文件”，选择 `.mid` / `.midi`。导入会复制到应用私有存储，保留原文件，无需USB键盘。选文件使用系统文件选择器，不需要整个存储空间的访问权限。
2. 默认按已经转为C调的文件处理；也可开启原调转C调并选择大调/关系小调。调外音可选择忽略、向上偏移半音、向下偏移半音；这是逐音近似，不能保留全部原和声。原调转换后再加共同移调，随后处理调外音，最后按八度折回。
3. 文件默认将超出C3–B5的音按12个半音折回，保留音名。可关闭；关闭后超出范围的音跳过。实时键盘的八度折回设置仍独立保留。
4. 多轨文件默认播放全部旋律音符，忽略GM通道10鼓音。可选择音轨，只演奏主旋律或减少和弦。速度/时间元数据始终读取；取消速度轨不会抹掉原文件的速度变化。
5. 可先“本地试听 MIDI”，成功准备后会自动取消本地静音并保留所设音量；继续本地试听同样处理。游戏自动演奏时回到已校准的原神琴界面，悬浮球菜单点“MIDI文件”→开始演奏，3秒倒计时后开始。无需点“开启映射”；游戏文件演奏不自动开本地声音。
6. 再次点“MIDI文件”会暂停并打开控制面板，可继续或从头停止。应用内也提供暂停/继续试听/停止。暂停、切离原神、屏幕变化、无障碍中断或触控取消时请求取消旧触控并释放按键。打开文件控制时发生手动触屏取消也会暂停。

文件播放支持 Format 0/1、PPQ刻度、SMPTE时间基准（含29.97）、运行状态、Note On/Off、Note On力度0的松键，以及CC64延音、CC120/123释放、CC121重置。读取全局速度变化，合并各轨事件；不强制量化、不吸附节拍格子。标准MIDI的时间通常是相对tick数，配合每拍刻度和速度变化转换为时间；并非所有文件直接存绝对毫秒。曲首、曲中和曲尾的空拍均保留。时值按Note Off及延音踏板释放决定。

两路使用同一映射后的毫秒时间线和单调时钟起点；本地将音符边界换算为渲染采样帧，游戏按Android手势数量限制切成多指短点按。同一琴键的同时起音合并；折回导致同键重叠时，后音先释放再重触发，重叠部分的最终松键取最后一个释放位置。同键1ms以内的起音会合并，重触发预留约1ms松键间隔，避免对同一屏幕位置同时注入多根手指。超出系统可表达的同时触控数量时提示减少音轨，不默默拆开和弦。

“琴类短点按”是文件当前唯一触控方式，每次最多24ms，密集重复键时缩短以留出松键间隔。每批预先计划最多800ms、受系统手势条数上限约束；回调晚到时保留未发音符，超过120ms暂停。文件“按音符时值按住”因原神崩溃反馈已停用。实时USB输入仍默认跟随按下/松开，与文件触控相互独立。

文件本地音源默认按时值进入短释音，避免截断爆音；也可选择自然衰减。WAV不会循环、拉伸或无限延长，采样结束就停止发声；长音暂停后继续会重新起音，再按剩余时值释放。文件播放和暂停期间暂停USB输入，点停止文件后恢复；文件结束后恢复实时采样的自然衰减设置。

支持文件≤16MiB、≤128轨、≤20万事件、时长≤6小时；Format 2须先导出为0或1。缺失Note Off的音在曲尾关闭，并显示提示。文件程序号、乐器变化、弯音、表情控制等不转换为游戏琴键，音色使用现有21键采样。

状态中的“音源起播迟到”和“触控最大迟到”是软件起播及各批提交的计时诊断，不包含游戏帧率、音频缓冲和硬件声学延迟。系统调度、屏幕刷新及游戏处理可能造成误差；音频断流和极密集触控仍需设备验证。没有华为真机或原神内的时序精度、和弦、持续触控或崩溃修复实测。

如果仍是最初0.1测试包，其签名不同，不能覆盖；此前0.1→0.2已要求卸载一次。0.2以后的工程保留同一个测试签名证书，以便覆盖更新。工程中的 signing/debug.keystore 是本原型专用测试证书，密码 android，不用于正式发布。

## 内置音色：无需逐个导入

使用本次上传 HarmonicKey.rar 中的21个 WAV，按文件名对应 C3–B5 自然音。全部是48kHz单声道PCM16，已逐个通过程序的 WAV 解码检查并内置 APK。SF2此次不使用，当前程序也不直接导入SF2。

每个键只触发它自己的采样。松键默认不截断采样的自然衰减，可在应用里取消“采样自然衰减”。该选项只影响WAV，本地延音踏板效果不会改变原神的触控声音。

已导入的自定义 WAV 优先于对应内置音；删除某个音的自定义采样会恢复内置 HarmonicKey。内置样本缺失或自定义文件无效时会回退到合成测试音色，并显示音色加载状态。

未修改用户原始WAV的音频字节；保留原文件音量差异。SAMPLE_MAPPING.json记录原始文件名、MIDI音高、长度、峰值和起音检查。它用于来源与映射核对，不是端到端延迟实测。

## 0.4 音频优化与试听

直接覆盖安装后，先点“停止音源和映射”，再启动后台音源，确认“采样 21/21键”。默认“低延迟”档。通过扬声器或有线耳机对比旧版的弹奏手感；需要映射时再返回原神开启。

- 输出使用系统报告的原生采样率、单声道 PCM16 和 AudioTrack 低延迟请求。实际是否采用低延迟模式在状态栏显示；设备可以不接受请求。
- 分离缓冲容量与实际使用量：容量留出调节余地，启动时主动请求更小的有效缓冲。低延迟/平衡/稳健分别请求设备原生块大小的2/3/4倍；系统可能限制实际值。
- 以最多64帧为一块处理起音和混音（此前128帧），降低程序内部等待新消息的粒度。48kHz下64帧约1.33ms；这是处理块时长，不是总延迟或保证值。
- 输出线程保持音频流运行，启动时预填充有效缓冲。启动前半秒不因预热欠载而扩容；之后每250ms检查缓冲不足次数，发现新增欠载就增大一个原生块，最多请求8个原生块且不超过系统容量。自动增大只在本次运行有效。
- MIDI音源队列、48个发声音符及混音/PCM输出数组预先分配，演奏时复用。测试音色改用波形查表与缓存衰减系数。状态文本在UI线程格式化，避免输出线程反复创建字符串。
- WAV加载时先转换到输出采样率；同采样率直接复用。这样避免每个同时发声的WAV在演奏时做插值。使用线性插值；原始采样文件不改写。
- WAV的防爆音淡入由3ms缩短到0.5ms，保留自然衰减。测试合成音色仍用3ms淡入。这个包络时间也不等于端到端延迟。

若听到卡顿/断音，先看“缓冲不足次数”是否持续增加，让自动增大机制适应；也可在音频缓冲中选“平衡”或“稳健”，点“保存设置”即可生效，无需重新开启无障碍。负载下降后，“重试所选档位的小缓冲”可恢复该档初始请求；若仍不稳定会再增大。

状态显示输出采样率、PCM格式、输出设备、系统性能模式、实际缓冲帧数、缓冲时长、欠载计数和自动增大次数。“缓冲时长”只是帧数除以采样率，没有包含MIDI传输、系统调度、音频硬件及耳机等延迟，不能当作按键到声音的实测值。换输出设备后应停止并重启音源重新适配。

本版仍用媒体音量通道；系统媒体音量为0时本地采样也会静音。游戏静音继续使用原神自己的音量设置。SF2仍未加入直接加载支持。

## USB MIDI和音源测试

1. 安装应用，点启动/重新连接后台音源。底部测试键可以不接MIDI键盘试声音。
2. 用支持数据与OTG的线/转接头连接键盘，刷新设备，选择USB设备及输出端口，再启动/重新连接。
3. 查看“收到起音”计数、“采样 21/21键”和本地声音。MIDI默认映射编号48–83的21个自然音，不响应MIDI通道10打击乐。
4. 可移调±24半音或按八度折回。两路使用同一音高映射，黑键若移调后没有对应自然音则两路忽略。
5. 保留系统媒体音量，用扬声器或有线耳机。华为后台启动管理应允许本应用后台活动；实际鸿蒙后台音频焦点行为仍需真机检查。

## 三点或五点校准

启用无障碍，进入原神21键琴界面。若前台检测失败，点悬浮球菜单“诊断/绑定”，确认实际游戏包名。

点“3点校准”选择：

- 稳健3点（推荐）：C3 → B3 → C5。横向间距用(C3到B3向量)/6，纵向间距用(C3到C5向量)/2，减小点位误差的累积。
- 快速3点：C3 → D3 → C4。横向间距用C3到D3向量，纵向间距用C3到C4向量。
- 5点核对：C3 → D3 → C4 → B3 → C5。用远端点推导，近端点核对；误差超过容差要求重测。

C3在下排左端，B3在下排右端，C4在中排左端，C5在上排左端。按等间距3×7格子推导，允许校准向量略带倾斜。

点完显示21个绿色圆圈，检查是否对齐琴键中心，再点右上角保存；可以重测或取消。校准过程不发送演奏点击。原0.2的逐键校准数据可继续使用，不强制重测。

只检查前台应用包名，不能识别是否在琴界面。退出琴界面前关闭映射；切离游戏会自动关闭映射，返回后重新开启。屏幕尺寸、UI布局改变需重测。

## 游戏静音与游戏开声：分别录制

两个快捷按钮操作原神自己的音量设置，均不调整系统媒体音量。系统媒体音量为0时，本地采样也会无声；保留它即可听本地采样。也可以手动在原神设置里调整总音量。

由于本程序没有直接修改原神内部音量的接口，快捷按钮使用你录制的屏幕操作：

1. 从21键琴界面开始，首次点悬浮球菜单“游戏静音”或“游戏开声”，选择开始录制。也可点“声音设置”，选择对应操作重新录制。
2. 正常操作原神：退出琴界面→打开设置→声音→静音录为0，开声录为你想要的大小→返回21键琴界面。开声和静音要分别录制。
3. 录制层接收单指点击或直线拖动，再转发到游戏。等待转发后录制层重新出现，期间不要连点。顶部中间显示已录步数，有保存和取消；完成后保存。
4. 以后从同样的21键琴界面点对应快捷按钮，重放这一套操作。可随时取消，若中断需自己返回琴界面。
5. 执行期间暂停琴键触控映射和MIDI文件播放，**实时键盘本地音源保持运行**。结束后确认游戏音量、回到琴界面，再开启映射或继续文件演奏。

每套最多40步，屏幕尺寸必须一致，每一步检查游戏前台。界面布局/设置页状态变化后需重新录制。该功能不能读取/验证游戏音量，执行完成只表示手势完成；实际音量由你确认。这个流程尚未在华为真机验证。

## 延迟和限制

本地音源直接接收MIDI，不等待触控或游戏发声。使用AudioTrack请求低延迟PCM16输出与有效缓冲调节，仍有设备音频缓冲和调度延迟；没有端到端毫秒实测。

游戏端使用无障碍触控。实时默认按住保持、松开释放，约2ms合并相邻输入，再按24ms短段续接；正在执行的手势结束后才能处理新键和松键。持续多指的新起音将用尽编号时会完整松键后重建，可能重新响一次仍按住的低音。兼容短点按模式约4ms合并不同起音，每次持续24ms，超过150ms的积压点击丢弃。游戏处理及系统回调可能让触控慢于本地音源；没有Shizuku后端。其他玩家听到的仍是游戏声音，外部音源不会修复游戏或网络延迟。

应用没有网络权限，不读取或保存界面文本；前台检测只取包名/窗口状态。无障碍权限用于本用户控制的映射、校准和已录静音/开声手势。

## 自定义WAV

可继续为每个自然音导入单独WAV，支持PCM16或IEEE float32、单/双声道、8–192kHz。单文件≤16MiB且≤30秒，输出采样率下的解码样本库上限64MiB。双声道平均为单声道，在后台加载线程按输出采样率重采样。不支持WAV extensible、24bit PCM、SF2、OGG、MP3或loop元数据。
